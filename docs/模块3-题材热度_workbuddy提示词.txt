请实现一个"当日事件驱动题材热度"Web 模块（A股复盘工具的第 3 个 Tab）。要求功能完整、无偏差，按下面的规格逐条实现，最后按"验收测试"自测并给我通过的证据。

【技术栈】Python 3.12 + Flask 后端（单文件即可）+ 原生 HTML/CSS/JS 前端 + SQLite 存储。
【关键依赖】使用本机自带的 hithink-finance CLI（用 hithink-finance <subcommand> ... --format json 调用；返回信封 {"ok":true,"data":{...}}，失败 {"ok":false,"error":{"message":...}}）。CLI 不存在时不能崩，返回错误码 CLI_MISSING。

【一、数据采集】三个源：
1) 人气榜 Top30：
   GET https://dq.10jqka.com.cn/fuyao/hot_list_data/out/hot_list/v1/stock?stock_type=a&type=hour&list_type=normal
   请求头带上：User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 ；Referer: https://www.10jqka.com.cn/ ；verify=False；timeout=15。
   只取 data.stock_list 前 30 条，映射：code→ticker，name，order→rank，rise_and_fall→change，tag.popularity_tag，tag.concept_tag→concepts（字符串要包成数组），analyse_title，analyse；再拼一个 text = analyse_title + " " + analyse + " " + concepts 用空格连接。
2) 热门话题：GET .../hot_list/v1/topic?type=hour → data.topic_list，字段 title/description/hot_value/jump_url；内部记 {title, desc, hot, url, text=title+" "+desc}；title 为空丢弃。
3) 个股异动原因（走 CLI）：
   hithink-finance special anomaly-list --format json 取 data.item（按 thscode 去重）；
   再 hithink-finance special anomaly-stock --thscodes a,b,c --format json（每批≤50）取原因；
   每条记 {thscode, ticker(=去掉.XX), name, change, text=(原始记录+原因记录里所有字符串递归拼接), source:"异动"}。
另需：hithink-finance special hot-stock-trend --thscode X --start-date <今-4天> --end-date <今天> --format json 取该股最近一次正整数 rank 作为 trendRank。
CLI 调用：subprocess，stdout/stderr 管道，text=True，encoding="utf-8"，CREATE_NO_WINDOW，超时 45~60 秒（超时要杀进程树），瞬时错误最多重试 1 次（退避 min(4, 0.6*2^n)+随机 0~0.25 秒），同时最多 2 个 CLI 进程，按参数哈希做内存+磁盘缓存（TTL：目录/成分股 12 小时、异动 120 秒、趋势 600 秒）。

【二、题材目录】两段：hithink-finance index catalog --tag cn_concept --format json 和 --tag industry；各取 data.item 的 name/thscode，合并去重成 catalog（约 700+ 项）。
成分股：hithink-finance index constituents --thscode <code> --format json 取 data.item 的 thscode/ticker/name。

【三、代码后缀规则】去掉结尾 .SH/.SZ/.BJ 后：6开头→.SH；0或3开头→.SZ；4/8/9开头→.BJ；其他→.SZ。

【四、关键词词典（必须原样使用）】
利好词 = ["收购","重组","并购","置入","注入","中标","签订","签约","合同","订单","获批","批准","许可","通过","突破","量产","投产","扩产","达产","交付","业绩增长","增长","扭亏","预增","超预期","创新高","涨价","提价","景气","回购","增持","举牌","战略合作","合作","政策支持","补贴","国产替代","专利","摘帽","涨价函","重大合同","业绩预增","订单饱满"]
利空词 = ["减持","清仓","质押","问询","立案","调查","处罚","罚款","警示","亏损","预亏","下滑","下降","终止","失败","退市","诉讼","仲裁","违约","逾期","减值","计提","商誉","解禁","被执行","冻结","违规","被查","风险提示","监管","停牌核查","澄清","不属实","终止合作"]

【五、归类判定 _theme_hit(题材名 name, 事件 ev)，命中任一即算命中】
(1) ev.concepts 里有元素完全等于 name；(2) name 出现在 ev.analyse_title 里；(3) 若 len(name)>=3：name 出现在 ev.text 里，或某个 concept 包含 name。循环时跳过 len(name)<2 的目录项。

【六、打分】
词典分：bull/bear = 文本中利好词/利空词出现次数之和（用 count，可重复计），net=bull-bear。
方向分 _direction_score(change, popularity_tag)：popularity_tag 非空→+3；涨跌幅≥7→+3；3~7→+2；0~3→+1；≤-7→-3；-7~-3→-2；-3~0→-1；其余→0。
人气权重 weight = 31-rank（有 rank）；无 rank 则 = 6。

【七、主流程】
0) CLI 不可用→{success:false,error:"CLI_MISSING",message:"题材热度功能需要本机安装 hithink-finance 数据组件"}；目录为空→{success:false,error:"指数目录获取失败"}。
1) 采三源；全空→{success:false,error:"当日无事件数据（非交易日或尚未开盘）"}。
2) 合并事件（键=thscode）：先放人气榜(source="人气榜")；再并入异动：已存在则把异动的 text 追加到已有 text 后并标记 anomaly，否则新增。
3) 话题→题材：每个话题算出词典分；对每个命中题材：topicHeat += hot_value/10000；topics 追加 {title,hot,desc}（同标题不重复）；bullWords 追加话题文本命中的利好词（去重）；bull/bear/net 累加。
4) 事件股→题材：对每个事件（text 为空跳过）：算词典分、方向分、weight、rank；对每个命中题材：若该股票已在该题材 members 里就跳过；members 追加 {thscode,ticker,name,rank,change,reason=analyse_title 或 text 前40字,source}；heat += weight；bullWords 追加命中的利好词；bull += lex.bull + (方向分>0?1:0)；bear += lex.bear + (方向分<0?1:0)；net += lex.net + 方向分。
5) 汇总：members 按 rank 升序（无 rank 记 999）；popHeat=heat；topicHeat=round(topicHeat,1)；heatScore=round(topicHeat+heat,1)；netScore=net；verdict=利好/利空/中性（net 正/负/零）；stockCount=len(members)；stockReasons=members 中 reason 非空的前 3 条 {name,reason,rank,change}；bullWords 取前 6。rows 按 (-heatScore,-netScore) 排序；bulls = verdict=="利好" 且 heatScore>=6；picks = bulls 前 6 个。
6) 成分股：对每个 picks 题材取成分股，剔除名称含 "ST"（忽略大小写/空格）或含 "退" 的；hotRank 用第 2 步人气榜的 ticker→rank 映射；对没有 hotRank 的股票补 trendRank，但要限流：全局预算 52 次，每题材最多 14 次，每次取的配额 = max(1, 全局剩余//剩余题材数)；stocks 排序键：有 hotRank→(0,hotRank)，有 trendRank→(1,trendRank)，否则→(2,999)；每题材只留前 stock_limit 个（默认 10）。
7) 合并 Top50：把 picks 的 stocks 按 ticker 合并去重，合并时 themes 列表累加（去重）、themeHeat 取最大、hotRank/trendRank 空则补齐；排序键：有 hotRank→(0,rank,0,"")，有 trendRank→(1,rank,0,"")，否则→(2,0,-themeHeat,ticker)；取前 50。
8) 落库（SQLite）：表 theme_heat_snapshot（唯一键 trade_date+theme_name，含 captured_at/heat_score/pop_heat/topic_heat/net_score/bull/bear/stock_total/stock_count/verdict/rank/reason_summary，写 allThemes 最多 20 条）、theme_top_stock（唯一键 trade_date+theme_name+stock_code，每题材最多 50 条）、theme_topic（唯一键 trade_date+title）、raw_payload（cache_key="themes:<date>"，整包 JSON）。
整包结果缓存 300 秒，并做 in-flight 去重。

【八、返回 JSON】{success:true, as_of:"YYYY-MM-DD HH:MM", eventCount, themeCount, bullCount, bearCount, sources:{hotlist,anomaly,topics}, topics:[{title,desc,hot,url}], rows:[题材对象，无 members], topStocks:[{thscode,ticker,name,hotRank,trendRank,change,themes:[],themeHeat}], stockTotal, stockRanked, allThemes:rows 前 20, method:"...", caveat:"事件源仅覆盖当日（热门话题15条 + 人气榜Top30 + 异动榜），且利好利空为关键词规则判定，非语义模型，可能漏判新说法。", elapsed}。

【九、HTTP 接口】
GET /api/event-themes?limit=6&stocks=20&date=YYYY-MM-DD（limit 夹紧 1~20，stocks 夹紧 3~50）：
- 传了 date：只读本地库；命中→原样返回并补 from_db=true、trade_date=date、给 topStocks 补 streak_days；未命中→HTTP 200 + {success:false,error:"NO_DATA",trade_date:date,message:"该交易日没有已保存的题材数据（当天程序可能没有运行）"}（不要 404）。
- 没传 date：先判断是否处于当日交易时段（交易日 且 09:15~15:05）；非交易时段→读库（当天场次交易日）命中就返回并补 from_db/trade_date/streak_days；交易时段→实时构建，成功才落库（trade_date=当前场次交易日），并补 streak_days。**非交易时段一律只读不写**（否则会覆盖上一交易日存档，不可恢复）。
GET /api/themes/dates?limit=60 → {success:true, dates:[降序日期]}（来自 theme_heat_snapshot 的 distinct trade_date）。
连续上榜 streak_days：从该交易日按交易日历往前逐日回推，连续每天排名≤30 的天数（含当天）；某天不在前30 或某天无该股人气榜数据即中断；只给当天在榜的股票。

【十、前端（原生 JS，无框架）】
Tab 切换时请求 /api/event-themes?limit=6&stocks=20[&date=] 并渲染四块：
1) 题材标签 #hot-themes：每个题材一个 <button class="theme-chip" onclick="filterTopByTheme('<名>',this)" title="<关联话题标题换行分隔/无关联话题>">，内含 chip-name「序号. 题材名」、chip-d1「利好 +netScore」（netScore>=0 加 up 类否则 down）、chip-d5「话题X万 · N只人气股」（无话题热度显示"无话题"）。
2) 说明 #hot-themes-note：「回看交易日 <date>　|　事件源：热门话题 N 条 + 人气榜 N 只 + 异动 N 只　|　识别题材 N 个（利好 N / 利空 N）　|　热度 = 话题热度(万) + Σ(31−人气榜排名)　|　<caveat>」；非回看模式首段改成「数据 <as_of>」。
3) 利好原因解读 #theme-reasons-body：每题材一张 reason-card，含头部「N. 题材名 / 利好 +netScore / 热度 heatScore」、事件区（话题标题 + hot/10000 保留1位万 + 摘要；无话题时提示"无关联热门话题，仅由人气股异动解读判定"）、个股区（stockReasons：名称 + 人气榜第N名 + 原因）、依据区（命中利好词 chips；无则"无命中利好词，由涨停/涨跌方向判定"）。
4) Top50 表 #top-stocks-body 列：排名 | 代码 | 名称 | 涨跌幅 | 所属题材 | 人气 | 连续上榜 | 题材热度。人气列：有 hotRank→"人气榜第 N 名"（强红）、有 trendRank→"热度第 N 名"（红）、否则"未上榜"（灰）；hotRank 行的排名用高亮徽章；名称可点击打开个股 K 线。note 文案：「合并 N 个利好题材的成分股（每题材取人气靠前的 20 只），去重后 N 只 → 按人气排名取前 N 只（其中 N 只有明确人气排名）。点击题材标签可筛选，点击名称可看 K 线。」
交互：filterTopByTheme 点标签筛选 Top50 中属于该题材的股票（再点取消、加 .chip-active、平滑滚动到表格）；clearTopFilter 清空；首次加载自动把最热题材填入手动输入框并触发一次分析。
日期块 #theme-date-chips：从 /api/themes/dates 渲染 <span class="day-chip has[ sel]" title="点击查看 <日期> 的题材数据" onclick="pickThemeDate('<日期>')">，点一下切该日、再点"看最新"回最新；无数据时显示"暂无已保存的题材数据"。
错误分支：error=="NO_DATA"→提示该日无存档（不回退实时）；error=="CLI_MISSING"→提示需要 hithink-finance 组件（不回退）；其他失败→回退到 /api/theme-hot?limit=12&lookback=5 的板块动量榜。

【十一、异常必须处理】CLI 缺失、目录为空、三源全空、话题为 0、涨跌幅非数字、一股多题材、同题材重复命中、ST/退市剔除、成分为 0、非交易日只读、参数越界、并发去重。
