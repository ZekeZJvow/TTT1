# Part A · 功能说明（人读）

## A1. 一句话
自动发现"当日正在发酵的利好题材"，并给出**每个题材的利好原因**和**相关个股人气 Top50**。

## A2. 它到底做了什么（5 步）
1. **采三类当日事件**
   - 同花顺**热门话题**（带热度值，例：80.4万）
   - 同花顺**人气榜 Top30** 的**异动解读**（analyse_title / analyse / 概念标签）
   - **个股异动原因**（当日异动股的原因文本）
2. **归类题材**：把上述事件文本去匹配**同花顺指数目录**（概念 + 行业，约 700+ 个），命中即归入该题材。
3. **判利好/利空**：用**关键词词典**（利好词/利空词）+ **涨跌方向**（涨跌幅、涨停标记）算一个净分 `net`；`net>0` = 利好，`net<0` = 利空，`=0` = 中性。
4. **算热度并排序**：`题材热度 = 话题热度(万) + Σ(31 − 人气榜排名)`；只保留**利好**且热度 ≥ 6 的题材，取前 6 个。
5. **出个股**：每个题材取**人气靠前的 20 只成分股**（剔除 ST/退市），合并去重后**按人气排名输出前 50 只**。

## A3. 页面上你能看到三块
| 区块 | 内容 |
|---|---|
| ① 题材标签区 | 6 个题材按钮：`序号.题材名`、`利好 +净分`、`话题X万 · N只人气股`；点按钮 → 筛选下面的 Top50；悬停 → 显示关联话题 |
| ② 各题材利好原因解读 | 每个题材一张卡片：事件（话题标题+热度+摘要）、个股解读（名称+人气榜第N名+原因）、命中利好词 |
| ③ 利好题材个股 Top50 | 表：排名 / 代码 / 名称 / 涨跌幅 / 所属题材 / 人气 / 连续上榜 / 题材热度；可点题材筛选 |
| ④ 日期切换 | 列出**本地库里已有题材数据的交易日**，点一下即回看那一天 |

## A4. 重要口径
- 只在**交易日盘中/盘后**采集；**非交易时段（含周末/节假日）只看本地库、且绝不写库**（防止把上一交易日的存档覆盖掉）。
- 每个题材的"利好原因"来自**真实事件文本**，不是拼凑的概念标签。
- 题材热度**无法回补历史**：只有程序当天跑过，才有那天的数据。

### B1.2 异动原因（走 CLI）
两步：
```

```

- 每条输出内部字段：
  - `thscode`、`ticker`(= thscode 去掉 `.XX`)、`name`、`change`
  - **`text` = 该股票"异动原始记录 + 原因记录"里所有字符串递归拼接**（把嵌套 JSON 里所有字符串都抓出来，用空格连接）
  - `source = "异动"`
- 该接口在**非交易日/盘前可能为空**，必须容忍返回 `[]`。

### B1.3 个股热度趋势（走 CLI，用于给"非人气榜个股"补一个排序依据）
```

  --start-date <今天-4天 YYYY-MM-DD> --end-date <今天 YYYY-MM-DD> --format json
```
- 取 `data.item` 里所有 `rank`（正整数）中的**最后一个**作为 `trendRank`；无则 `None`。
- 缓存 TTL 600 秒。

### B1.4 代码后缀规则（`_to_thscode`）
```
去掉结尾的 .SH/.SZ/.BJ；
以 6 开头            -> + ".SH"
以 0 或 3 开头        -> + ".SZ"
以 4/8/9 开头         -> + ".BJ"
其他                 -> + ".SZ"
```

### B1.5 CLI 调用规范（必须照做）
- 统一返回信封：成功 `{"ok": true, "data": {...}}`；失败 `{"ok": false, "error": {"message": ...}}`（或非 0 退出码）。
- 调用方式：`subprocess.Popen([CLI] + args, stdout=PIPE, stderr=PIPE, text=True, encoding="utf-8", errors="replace", creationflags=CREATE_NO_WINDOW)`。
- **超时**：默认 45s（异动 60s、目录/成分股 60s）；超时必须**杀掉整个进程树**。
- **重试**：仅对"瞬时错误"重试，最多 1 次，退避 `min(4, 0.6*2^n) + random(0,0.25)` 秒。
- **并发闸门**：同时最多 2 个 CLI 进程（`HITHINK_FINANCE_CONCURRENCY`，上限 4）。
- **缓存**：按 `sha256(JSON(args))` 做内存 + 磁盘（SQLite）缓存，TTL 分级：
  目录 12 小时 / 成分股 12 小时 / 异动 120 秒 / 趋势 600 秒。

## B4. 归类算法：一条事件命中一个题材的判定 `_theme_hit(题材名, 事件)`
按顺序，命中任意一条即为"命中"：
1. 事件的概念标签里有**完全等于**题材名 → 命中（最可靠）
2. 题材名出现在事件的 **analyse_title**（解读标题）里 → 命中
3. 若 `len(题材名) >= 3`：
   a. 题材名出现在事件的长文本 `text` 里 → 命中
   b. 或某个概念标签**包含**题材名 → 命中
> 另外：所有归类循环里都跳过 `len(题材名) < 2` 的目录项。

## B5. 打分与判定

### B5.1 词典分 `_lexicon_score(text)`
```
bull = Σ (text 中出现 BULL_WORDS[i] 的次数)     # 用 count，允许重复计数
bear = Σ (text 中出现 BEAR_WORDS[i] 的次数)
net  = bull - bear
```

### B5.2 方向分 `_direction_score(change, popularity_tag)`
| 条件 | 分值 |
|---|---|
| `popularity_tag` 非空（例：首板涨停/2天2板） | **+3** |
| 涨跌幅 ≥ 7 | +3 |
| 3 ≤ 涨跌幅 < 7 | +2 |
| 0 < 涨跌幅 < 3 | +1 |
| 涨跌幅 ≤ -7 | -3 |
| -7 < 涨跌幅 ≤ -3 | -2 |
| -3 < 涨跌幅 < 0 | -1 |
| 其余（含 0 / 解析失败） | 0 |

### B5.3 人气权重
```
weight = (31 - rank)  若 rank 存在
       = 6            若 rank 不存在（异动股基准分）
```

## B6. 主流程（严格按此顺序）

### 步骤 0 · 前置检查
- CLI 不可用 → 立刻返回 `{"success": false, "error": "CLI_MISSING", "message": "题材热度功能需要本机安装 hithink-finance 数据组件（人气榜查询与动态选股不受影响）"}`。
- 取 `catalog`（B2）。空 → 返回 `{"success": false, "error": "指数目录获取失败"}`。

### 步骤 1 · 采集
`hot = 人气榜`（≤30）、`anom = 异动`、`topics = 话题`。
三者**全空** → 返回 `{"success": false, "error": "当日无事件数据（非交易日或尚未开盘）"}`。

### 步骤 2 · 合并事件（以 thscode 为键）
```
events = {}
先放入 hot（source="人气榜"）
再并入 anom：
   若该 thscode 已存在 -> 把 anom 的 text 追加到已有 text 后面，并标记 anomaly=True
   若不存在          -> 新增该条
event_list = events.values() 中 thscode 非空的
```

### 步骤 3 · 归类循环 A：话题 → 题材
对每个话题 `tp`：
- `lex_t = _lexicon_score(tp.text)`
- 遍历 catalog，对每个 `len(name)>=2` 且 `_theme_hit(name, {concepts:[], analyse_title: tp.title, text: tp.text})` 成立的题材：
  - 若题材首次出现 → 初始化结构（见 B7.1）
  - `th.topicHeat += tp.hot / 10000.0`（**万为单位**）
  - 若该话题标题未记录过 → `th.topics` 追加 `{title, hot, desc}`
  - 把 `tp.text` 命中的 BULL_WORDS 追加进 `th.bullWords`（去重）
  - `th.bull += lex_t.bull`；`th.bear += lex_t.bear`；`th.net += lex_t.net`

### 步骤 4 · 归类循环 B：事件股 → 题材
对 `event_list` 每个事件 `ev`（`text` 为空则跳过）：
- `lex = _lexicon_score(ev.text)`；`dscore = _direction_score(ev.change, ev.popularity_tag)`；`rank = ev.rank or 0`；`weight = 31-rank`（rank=0 时 = 6）
- 遍历 catalog，对 `len(name)>=2` 且 `_theme_hit(name, ev)` 成立的题材：
  - 初始化（若首次）
  - 若该股票已在此题材的 members 里 → **跳过**（去重）
  - members 追加 `{thscode, ticker, name, rank, change, reason, source}`
    - **reason** = `analyse_title.strip()`；若为空 → 取 `text` 前 40 字
  - `th.heat += weight`
  - `th.bullWords` 追加 `ev.text` 命中的 BULL_WORDS（去重）
  - `th.bull += lex.bull + (1 if dscore>0 else 0)`
  - `th.bear += lex.bear + (1 if dscore<0 else 0)`
  - `th.net  += lex.net + dscore`

### 步骤 5 · 汇总每个题材
```
members 按 rank 升序（无 rank 用 999）
popHeat    = heat
topicHeat  = round(topicHeat, 1)
heatScore  = round(topicHeat + popHeat, 1)
netScore   = net
verdict    = "利好" if net>0 else ("利空" if net<0 else "中性")
stockCount = len(members)
stockReasons = members 中 reason 非空的 前 3 条 → [{name, reason, rank, change}]
bullWords  = bullWords[:6]
```
然后：
```
rows 按 (-heatScore, -netScore) 排序
bulls  = [r for r in rows if r.verdict=="利好" and r.heatScore >= min_heat]   # min_heat 默认 6
picks  = bulls[:limit]                                                        # limit 默认 6
```

### 步骤 6 · 取成分股 + 补人气 + 排序
```
pos_rank = { 人气榜个股 ticker: rank }        # 来自 hot
trend_budget = 52                            # 全局预算
for th in picks:
    cons = index constituents --thscode th.thscode     # 取 data.item
    过滤：name 含 "ST"（忽略大小写/空格）或含 "退" 的剔除
    stocks = [{thscode, ticker, name, hotRank: pos_rank.get(ticker), trendRank: None, change: None}]
    need = stocks 中 hotRank 为空的，按 name 排序
    share = max(1, trend_budget // max(1, len(picks) - picks.index(th)))
    for s in need[:min(14, share)]:                    # 每题材最多补 14 个
        if trend_budget <= 0: break
        trend_budget -= 1
        s.trendRank = 最近一次热度排名（B1.3）
    stocks 排序键：
        hotRank 存在      -> (0, hotRank)
        trendRank 存在    -> (1, trendRank)
        否则              -> (2, 999)
    th.stocks     = stocks[:stock_limit]               # 默认 10，前端传 20
    th.stockTotal = len(stocks)
```

### 步骤 7 · 合并 → 去重 → Top50
```
merged = {}
for th in picks:
    for st in th.stocks:
        key = st.ticker or st.thscode
        if key not in merged:
            merged[key] = dict(st); merged[key].themes=[th.name]; merged[key].themeHeat=th.heatScore
        else:
            merged[key].themes 追加 th.name（去重）
            merged[key].themeHeat = max(旧值, th.heatScore)
            补齐 hotRank / trendRank（原来为空才补）

top_stocks = sorted(merged.values(), key=_sk)[:50]
_sk(x):
    有 hotRank   -> (0, hotRank, 0.0, "")
    有 trendRank -> (1, trendRank, 0.0, "")
    否则         -> (2, 0, -themeHeat, ticker)
```
> 即：**人气榜个股优先（按名次升序）→ 其次热度榜个股 → 最后未上榜的按题材热度降序**。

### 步骤 7.5 · 补「涨跌幅」（可选但建议）

Top50 的涨跌幅按下面顺序补齐，取到即止：
1. 当日**人气榜**里的 `rise_and_fall`（Top30 免费自带）；
2. 其余个股走一次**行情快照**：`hithink-finance market snapshot --thscodes <逗号分隔> --format json`，
   取 `data.item[].price_change_ratio_pct`；
3. **历史回放**时（读本地库），改用本地日K：`daily_kline(trade_date, stock_code)` 的 `change_pct`。

> 三处都取不到 → 前端显示「无」。**注意**：不要在非交易时段用实时快照去补历史日期（会写脏历史口径）。

| `raw_payload` | 整包 JSON 回放 | cache_key = `themes:<trade_date>`, payload_json | cache_key |

- `theme_heat_snapshot` 写入 `allThemes`（**最多 20 个**，`rank` 用接口给的 rank 或序号）。
- `theme_top_stock` 每题材最多写 **50** 条（成分股 ticker 需清洗为纯数字）。
- **回放**：`load_event_themes(date)` = 读 `raw_payload['themes:<date>']` 的 JSON 原样返回。
- **可选日期**：`theme_dates(limit)` = `SELECT DISTINCT trade_date FROM theme_heat_snapshot ORDER BY trade_date DESC LIMIT n`。

## B9. 缓存
- 整包结果缓存 **300 秒**，键 `event-themes:<ns>:<limit>:<stock_limit>:<min_heat>`；同一时刻重复请求**合并为一次**（in-flight 去重），失败可回退到过期缓存。
- CLI 级缓存见 B1.5。

## B10. HTTP 接口契约

### B10.1 `GET /api/event-themes?limit=6&stocks=20&date=YYYY-MM-DD`
`limit` 默认 6（夹紧 1..20）；`stocks` 默认 10（夹紧 3..50）。分支**严格**如下：

1. **传了 `date`** → 只读本地库 `load_event_themes(date)`
   - 命中 → 原样返回，并补 `from_db=true`、`trade_date=date`、给 topStocks 补 `streak_days`
   - 未命中 → **HTTP 200** + `{"success": false, "error": "NO_DATA", "trade_date": date, "message": "该交易日没有已保存的题材数据（当天程序可能没有运行）"}`（**不要 404**）
2. **没传 `date`**：
   - `live = 是否处于当日交易时段（交易日 且 09:15 ≤ 现在 ≤ 15:05）`
   - 若 **not live**：读库 `load_event_themes(当前场次交易日)`；命中 → 返回并补 `from_db`、`trade_date`、`streak_days`
     - 当前场次交易日 = 今天（若今天是交易日）否则最近已完成交易日
   - 若 **live**：实时构建 `build_event_themes(limit, stocks)`
     - 成功 **且 live** → **才**落库（trade_date = 当前场次交易日）+ 补 streak
     - ⚠️ **非交易时段一律只读不写**（否则会把上一交易日的收盘存档覆盖掉，不可恢复）

### B10.2 `GET /api/themes/dates?limit=60`
返回 `{"success": true, "dates": ["2026-10-08", "2026-09-30"]}`（降序，最多 200 条）。

### B10.3 连续上榜（`streak_days`）
- 定义：从该交易日**按交易日历往前逐日回推**，连续每一天都"排名 ≤ 30"的天数（含当天）。
- 中断条件：某天不在前 30，**或**某天库里没有该股人气榜数据（保守中断）。
- 只给当天在榜的股票返回计数。

## B12. 异常与边界（全部必须处理）
1. CLI 不可用 → `CLI_MISSING`，不崩。
2. 指数目录为空 → `指数目录获取失败`。

9. 成分股为 0 → 该题材 stocks=[]，不报错。
10. 非交易日/盘后 → 只读库、不写库。
11. `limit`/`stocks` 越界 → 夹紧到合法范围。
12. 请求并发 → 用 in-flight 去重，避免重复采集。

【五、归类判定 _theme_hit(题材名 name, 事件 ev)，命中任一即算命中】
(1) ev.concepts 里有元素完全等于 name；(2) name 出现在 ev.analyse_title 里；(3) 若 len(name)>=3：name 出现在 ev.text 里，或某个 concept 包含 name。循环时跳过 len(name)<2 的目录项。

【六、打分】
词典分：bull/bear = 文本中利好词/利空词出现次数之和（用 count，可重复计），net=bull-bear。
方向分 _direction_score(change, popularity_tag)：popularity_tag 非空→+3；涨跌幅≥7→+3；3~7→+2；0~3→+1；≤-7→-3；-7~-3→-2；-3~0→-1；其余→0。
人气权重 weight = 31-rank（有 rank）；无 rank 则 = 6。

【七、主流程】
0) CLI 不可用→{success:false,error:"CLI_MISSING",message:"题材热度功能需要本机安装 hithink-finance 数据组件"}；目录为空→{success:false,error:"指数目录获取失败"}。
1) 采三源；全空→{success:false,error:"当日无事件数据（非交易日或尚未开盘）"}。
2) 合并事件（键=thscode）：先放人气榜(source="人气榜")；再并入异动：已存在则把异动的 text 追加到已有 text 后并标记 anomaly，否则新增。
3) 话题→题材：每个话题算出词典分；对每个命中题材：topicHeat += hot_value/10000；topics 追加 {title,hot,desc}（同标题不重复）；bullWords 追加话题文本命中的利好词（去重）；bull/bear/net 累加。
4) 事件股→题材：对每个事件（text 为空跳过）：算词典分、方向分、weight、rank；对每个命中题材：若该股票已在该题材 members 里就跳过；members 追加 {thscode,ticker,name,rank,change,reason=analyse_title 或 text 前40字,source}；heat += weight；bullWords 追加命中的利好词；bull += lex.bull + (方向分>0?1:0)；bear += lex.bear + (方向分<0?1:0)；net += lex.net + 方向分。
5) 汇总：members 按 rank 升序（无 rank 记 999）；popHeat=heat；topicHeat=round(topicHeat,1)；heatScore=round(topicHeat+heat,1)；netScore=net；verdict=利好/利空/中性（net 正/负/零）；stockCount=len(members)；stockReasons=members 中 reason 非空的前 3 条 {name,reason,rank,change}；bullWords 取前 6。rows 按 (-heatScore,-netScore) 排序；bulls = verdict=="利好" 且 heatScore>=6；picks = bulls 前 6 个。
6) 成分股：对每个 picks 题材取成分股，剔除名称含 "ST"（忽略大小写/空格）或含 "退" 的；hotRank 用第 2 步人气榜的 ticker→rank 映射；对没有 hotRank 的股票补 trendRank，但要限流：全局预算 52 次，每题材最多 14 次，每次取的配额 = max(1, 全局剩余//剩余题材数)；stocks 排序键：有 hotRank→(0,hotRank)，有 trendRank→(1,trendRank)，否则→(2,999)；每题材只留前 stock_limit 个（默认 10）。
7) 合并 Top50：把 picks 的 stocks 按 ticker 合并去重，合并时 themes 列表累加（去重）、themeHeat 取最大、hotRank/trendRank 空则补齐；排序键：有 hotRank→(0,rank,0,"")，有 trendRank→(1,rank,0,"")，否则→(2,0,-themeHeat,ticker)；取前 50。
8) 落库（SQLite）：表 theme_heat_snapshot（唯一键 trade_date+theme_name，含 captured_at/heat_score/pop_heat/topic_heat/net_score/bull/bear/stock_total/stock_count/verdict/rank/reason_summary，写 allThemes 最多 20 条）、theme_top_stock（唯一键 trade_date+theme_name+stock_code，每题材最多 50 条）、theme_topic（唯一键 trade_date+title）、raw_payload（cache_key="themes:<date>"，整包 JSON）。
整包结果缓存 300 秒，并做 in-flight 去重。

【八、返回 JSON】{success:true, as_of:"YYYY-MM-DD HH:MM", eventCount, themeCount, bullCount, bearCount, sources:{hotlist,anomaly,topics}, topics:[{title,desc,hot,url}], rows:[题材对象，无 members], topStocks:[{thscode,ticker,name,hotRank,trendRank,change,themes:[],themeHeat}], stockTotal, stockRanked, allThemes:rows 前 20, method:"...", caveat:"事件源仅覆盖当日（热门话题15条 + 人气榜Top30 + 异动榜），且利好利空为关键词规则判定，非语义模型，可能漏判新说法。", elapsed}。

【九、HTTP 接口】
GET /api/event-themes?limit=6&stocks=20&date=YYYY-MM-DD（limit 夹紧 1~20，stocks 夹紧 3~50）：
- 传了 date：只读本地库；命中→原样返回并补 from_db=true、trade_date=date、给 topStocks 补 streak_days；未命中→HTTP 200 + {success:false,error:"NO_DATA",trade_date:date,message:"该交易日没有已保存的题材数据（当天程序可能没有运行）"}（不要 404）。
- 没传 date：先判断是否处于当日交易时段（交易日 且 09:15~15:05）；非交易时段→读库（当天场次交易日）命中就返回并补 from_db/trade_date/streak_days；交易时段→实时构建，成功才落库（trade_date=当前场次交易日），并补 streak_days。**非交易时段一律只读不写**（否则会覆盖上一交易日存档，不可恢复）。
GET /api/themes/dates?limit=60 → {success:true, dates:[降序日期]}（来自 theme_heat_snapshot 的 distinct trade_date）。
连续上榜 streak_days：从该交易日按交易日历往前逐日回推，连续每天排名≤30 的天数（含当天）；某天不在前30 或某天无该股人气榜数据即中断；只给当天在榜的股票。

【十、前端（原生 JS，无框架）】
